# 减重训练风险闭环

本仓库维护"承诺与争议处置后端"的领域事件交换约定、只追加事件存储、退款规则与只读视图。
针对门店把口头承诺写成不同版本、退营时分别改合同备注/体重记录/退款原因、以删除不良记录
为赔付条件等问题，系统把每一条事实（广告素材、销售话术、合同版本、付款、阶段测量、安全事件、
请假退营、投诉证据、退款协议）都落为**只追加事件**：修订只能以新事件表达，原始记录永远可追溯。

## 目录

- `contracts/domain.schema.json`：领域对象与事件名称约定。
- `data/sample.json`：一条可用于本地联调的示例事件。
- `src/envelope.py`：事件信封的基础字段校验（事件类型/聚合类型枚举）。
- `src/store.py`：JSONL 只追加事件存储，跨进程命令锁、每聚合版本号、崩溃恢复重放。
- `src/state.py`：从日志重放出的只读聚合投影。
- `src/refund_rules.py`：按签约时冻结承诺计算退款候选（健康/未履行/反悔三套规则）。
- `src/domain.py`：领域服务（命令、角色权限、不变量、视图、月度核对）。
- `src/cli.py`：校验事件与输出核对/消费者/门店视图的命令入口。
- `tests/`：36 条回归测试，含销售离职、分期退款、迟到投诉、并发和解等场景。

## 核心约定

### 事实只追加，来源与有效期冻结

- 广告素材（`ad_material`）与销售话术（`sales_script`）分别登记，冻结来源定位、
  内容指纹、承诺口径与有效期；撤回（`PROMISE_RETIRED`）不删除历史。
- 签约（`CONTRACT_SIGNED`）把当时有效的承诺**整体快照**进合同。事后撤广告、换话术版本，
  已签合同的退款口径都不变——消费者 API 展示的正是这个采用版本。
- 阶段测量与安全事件只能追加（`MEASUREMENT_RECORDED` / `SAFETY_INCIDENT_RECORDED`），
  系统里不存在修改或删除它们的命令；业绩人员只能 `CONTRACT_NOTE_APPENDED` 追加说明。
- 退营原因登记后不可改写。

### 证据回执：完整重传一次，标识相同而内容变化立即锁案

- 同一回执标识 + 相同金额/文件指纹/提供方的重传按幂等处理，只计一次。
- 标识相同但金额、指纹或提供方变化：回执标记污染（`RECEIPT_TAINTED`），案件**立即锁定**
  （`CASE_LOCKED`），锁定期间停止退款批准与支付。
- 证据保全期限（`EVIDENCE_HELD`）作为事件保存，进程崩溃恢复后原样重建，不丢失期限。
- 争议专员只能调取双方可见（`visibility=mutual`）材料；内部材料仅监管/审计可见。

### 退款：候选可计算，三权分立，结算不能掩盖调查

- 系统按签约时承诺快照与不可改写记录生成退款候选：
  - **健康原因**：关联安全事件；健康归因或严重事件 → 已付全额；否则按未交付课时比例，不收手续费。
  - **服务未履行**：未履行比例 × 已付款；签约时承诺的"不瘦退款"结果保证（依原始测量判定）
    未达成时可主张全额。
  - **普通反悔**：执行签约时冻结的冷静期/阶梯退费表，表外按未消费比例与约定手续费。
- **调解（mediator）、退款批准（refund_approver）、监管答复（regulatory_officer）由不同人完成**：
  批准人不得是本案调解人，监管答复人不得是调解人或本案批准人。
- 只能批准系统计算出的候选金额；分期支付净额不得超过批准额；同一支付标识不得重复付款。
- 已经付出的和解款只能通过**冲正（REVERSED）或补付（TOPUP）**调整；结算关闭要求净额
  恰好等于批准额、案件未锁定、**没有进行中的监管调查**。

### 跨门店续营与视图

- 跨店续营（`CASE_TRANSFERRED`）把未结争议连同学员新合同继承到新店，门店待办随之转移；
  已结案件不转移。
- 消费者 API：展示每份合同采用的承诺版本、每笔退款候选、依据、批准与净付金额。
- 门店视图：只看到当前归属本店的未结案件待办。
- 月度核对：承诺兑现（结果承诺达成情况）、退款台账（含超额付款）、未结监管调查、
  锁定案件、到期证据保全。

### 并发与故障恢复

- 每条命令在跨进程文件锁 + 进程内锁的临界区内执行，进入时从日志重放；并发和解只有一方提交。
- JSONL 每行一个事件，单行追加写入；恢复时校验事件标识唯一与每聚合版本连续，
  断档/重复日志直接拒绝启动。支付标识幂等，保证故障恢复后不重复付款。

## 本地运行

校验示例事件：

```bash
python3 -m src.cli validate data/sample.json
```

对一份事件日志输出月度核对 / 消费者视图 / 门店待办：

```bash
python3 -m src.cli reconcile  events.jsonl 2026-10
python3 -m src.cli consumer   events.jsonl consumer-1
python3 -m src.cli store-todo events.jsonl mgr
```

运行测试：

```bash
python3 -m unittest discover -s tests
```

编译检查：

```bash
python3 -m compileall -q src tests
```

这些命令只使用 Python 标准库，不需要单独运行数据库或其他服务。

## 角色

集团营销 `marketing`、销售 `sales`、店长 `store_manager`、教练 `coach`、安全员
`safety_officer`、争议专员 `dispute_specialist`、调解人 `mediator`、退款批准人
`refund_approver`、退款支付员 `refund_payer`、结算员 `settlement_officer`、
监管专员 `regulatory_officer`、审计 `auditor`、消费者 `consumer`，以及负责人员
登记/停用的系统角色 `group_admin`。员工离职后历史署名保留，但不能再执行任何业务动作。
